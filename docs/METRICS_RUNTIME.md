# Исполняемый сбор метрик

`node tools/metrics_capture.mjs start --project projects/demo --stage research --session ID`

Перед ожиданием человека: `node tools/metrics_capture.mjs pause --project projects/demo`.
После ответа: `node tools/metrics_capture.mjs resume --project projects/demo`.
На границе завершения: `node tools/metrics_capture.mjs finish --project projects/demo --result "Завершено"`.

### Точные токены OpenCode

Для работы в OpenCode сначала откройте сессию этого репозитория и получите её ID (`ses_...`) через список сессий OpenCode. Перед этапом:

`node tools/metrics_capture.mjs start --project projects/demo --stage research --session ses_ВАШ_ID --opencode-db default`

После этапа: `node tools/metrics_capture.mjs finish --project projects/demo --result "Исследование завершено"`.

`default` указывает на базу установленного OpenCode в профиле пользователя; если она лежит в другом месте, передайте полный путь вместо `default`. Сборщик читает только счётчики указанной сессии, проверяет её принадлежность репозиторию и сохраняет разницу между началом и концом. Кэш складывается из чтения и записи; выход включает отдельный счётчик рассуждения. Временная копия базы удаляется сразу после чтения. Если сессии нет или счётчики уменьшились, запись отклоняется. При отсутствии прироста повторите `finish` после завершения ответа; только для этапа без вызова модели допускается `--allow-empty yes`, тогда токены будут `н/д`. Одну сессию нельзя одновременно использовать для независимых этапов: тогда её расход нельзя разделить точно.

Эта процедура учитывает вызовы OpenCode. Токены текущего чата ChatGPT/Codex в его локальной базе отсутствуют; без отчёта исполнителя они остаются `н/д`. Применимость проверена на схеме OpenCode 2.2.5; при изменении схемы программа завершится ошибкой до записи.

Контрольная точка находится в блоке `## Текущие метрики` файла `state.md`. Одна завершённая запись добавляется в `events.csv`. Если после записи в CSV очистка контрольной точки прервалась, повторный `finish` очистит её без дублирования события. Повторный call_id отклоняется. Скрипт не запускает модель и не собирает данные в фоне.

Для токенов добавьте к `finish` аргумент `--usage ПУТЬ`. Файл должен быть отчётом ровно одного вызова, нормализованным исполнителем:

```json
{
  "capture_id": "ID из команды start",
  "call_id": "устойчивый ID вызова исполнителя",
  "provider": "openai",
  "model": "имя модели из отчёта",
  "usage": { "input": 120, "output": 30, "cache": 10 },
  "input_includes_cache": false,
  "output_includes_reasoning": true
}
```

`input` означает вход без кэша, `cache` — самостоятельную непересекающуюся категорию. Если исполнитель не сообщает эти поля и их смысл, не создавайте приблизительный отчёт: токены будут `н/д`. Не сохраняйте в отчёте запросы, ответы, ключи и сведения других проектов. Этот формат не доказывает подлинность стороннего отчёта: интеграция должна получать его непосредственно от доверенного исполнителя. Без такой интеграции доступны только локально измеренные секунды.

Стоимость рассчитывается только из заполненного человеком `docs/PRICING.md`. Формат поля «Единицы и ставки…» для одного модельного тарифа: `openai/имя:вход=1.25;выход=5;кэш=0.2;единица=1000000`; правило отнесения — `сумма по токенам вызова`. Требуются валюта, границы действия тарифа в формате YYYY-MM-DD, ссылка/документ и дата источника. При отсутствии любого поля стоимость `н/д`. Расчётная стоимость округляется до восьми знаков и сопровождается валютой и источником в `источник метрики`. Тарифы для нескольких моделей в одной ячейке пока не поддержаны.

Для сводки в PowerShell: `& .\tools\python.ps1 -B tools/cost_summary.py projects/demo/events.csv`. Скрипт находит Python в рабочем окружении или системную установку. Исторические данные не дополняются задним числом.
