# Повторный аудит репозитория

Дата: **2026-11-21**. Предыдущая проверка: [AUDIT.md](AUDIT.md), 2026-11-15.

Репозиторий — файловые инструкции агенту продуктового руководителя: постановка → сбор → исследование → варианты → выбор человека → две стратегии и план проверки → проверка документов → решение. Проверяемый режим — один руководитель и последовательная работа с проектом, не многопользовательский сервис.

**Итог: документальные несоответствия в основном устранены; появился след завершённой учебной демонстрации с двумя независимыми отзывами. Воспроизводимость актуального набора правил, защитные сценарии и полный учёт затрат ещё не доказаны.** Не требуется сначала строить оркестратор: ближайшая полезная работа — проверки и сохранение свидетельств.

- **«Подтверждено»** ниже означает только конкретный результат, для которого есть запись events.csv или отчёт critic/*-review-*.md. Это локальное свидетельство, не независимое удостоверение всей истории действий. Область подтверждения указана рядом.
- **«Описано, не подтверждено»** — правило, сценарий или возможность написаны, но требуемого следа исполнения нет. Существование инструкции не доказывает её соблюдение.
- **«Не выполнено / свидетельства нет»** — соответствующий результат отсутствует в просмотренных файлах. Это не утверждение об отсутствии действий вне этой копии.
- README, state, verify и changelog помогают сопоставить артефакты, но сами по себе не повышают статус поведения до «подтверждено». Внешние исследовательские страницы в этом аудите не перечитывались.

## 2. Новые находки

Ниже — новые конкретные ограничения и несоответствия. Непройденные smoke-тесты, отсутствующий revisit и неполные старые claims уже были находками первого аудита и повторно за новые не выдаются.

### Н1. Новая демонстрация не сохраняет проверяемый диалог — высокий приоритет

- **Где:** projects/demo/events.csv:19–25; projects/demo/critic/strategy-review-1.md:44–47; projects/demo/verify/consistency-review.md:42–44. Transcript в проекте отсутствует.
- **Ситуация:** нужно доказать, что стратегия начата после реального ответа «02», а не после подстановки записи. Журнал даёт порядок и текст решения, но сами независимые проверяющие прямо не видели исходное сообщение. Поэтому подтверждается согласованность записи выбора, не подлинность сообщения и не отсутствие ручных обходов.
- **Минимальная доработка:** на следующем запуске сохранить точные реплики и вызовы инструментов по tests/README.md:22–30; прошлый transcript по памяти не сочинять.
- **Если отложить:** демонстрация останется локальным следом исполнения, а не воспроизводимым протоколом. Это не доказательство нарушения выбора человеком.

### Н2. Частичный временной отрезок записан как метрика завершённого шага — средний приоритет

- **Где:** projects/agent-skills/events.csv:13; projects/agent-skills/metrics-summary.md:12,20,29; skills/metrics/SKILL.md:33–38,58; projects/_template/FIELDS.md:37.
- **Ситуация:** поле секунды строки тип=шаг равно 456.4225492, но источник исключает первоначальное чтение и итоговое оформление. Читатель CSV видит числовую длительность всего исполнения шага, хотя правило при неполном измерении требует н/д. Текстовая оговорка делает сводку честнее, но не устраняет противоречие машинного поля правилу.
- **Минимальная доработка:** по отдельному поручению явно сохранить исходное число и границы как известную часть, полную длительность шага обозначить н/д и согласовать вывод сводки. Не удалять измерение и не придумывать недостающие секунды. Скрипт сейчас берёт сумму только из числового поля; после исправления ячейки неполную известную часть нужно показывать отдельно, не начислять второй строкой затрат.
- **Если отложить:** покрытие может принять частично измеренное исполнение за полностью измеренное. Полное время проекта в текущей сводке всё же не объявлено известным.

### Н3. Обновлённый читатель затрат не включён в CI, нового результата его тестов нет — средний приоритет

- **Где:** tests/test_cost_summary.py:31–108; tools/cost_summary.py:35–49,84–91,111–126; .github/workflows/quality.yml:17–90; docs/DECISIONS.md:72–76.
- **Ситуация:** после изменения формата токенов добавлены семь unit-тестов, но workflow запускает только Markdown, поиск секретов и репозиторную политику. Даже успешный такой CI не проверит арифметику нового читателя. Запись о четырёх старых тестах в docs/CHANGELOG.md:65 не доказывает запуск нынешних семи и по принятому здесь правилу не является достаточным свидетельством прохождения.
- **Минимальная доработка:** отдельно разрешить и выполнить python -B -m unittest discover -s tests -p test_cost_summary.py, сохранить вывод и версию файлов, затем добавить эту же проверку в CI. Изолированный тест скрипта не заменяет smoke-тест агента.
- **Если отложить:** регрессия разбивки вход/выход/кэш может пройти репозиторный CI незамеченной. Конкретная ошибка арифметики текущим чтением не установлена.

### Н4. Доказательство demo относится к прежнему, не к актуальному набору правил — высокий приоритет для заявления «всё работает»

- **Где:** projects/demo/events.csv:2–41; projects/demo/state.md:4,46–48; docs/CHANGELOG.md:3–8,12–25; tests/run-log.md:3.

Из файлов нельзя установить, что полный учебный цикл прошёл уже после добавления этих правил; одинаковой календарной даты недостаточно. Это пробел доказательства, не установленное задним числом нарушение старого прогона.
- **Минимальная доработка:** следующий цикл провести на зафиксированной версии; при недоступном Git сохранить идентификатор снимка файлов, не подделывая хэш коммита. Старый demo оставить историческим свидетельством своего объёма.
- **Если отложить:** корректный старый результат будут ошибочно предъявлять как тест нового учёта и возобновления.

### Н5. Ограничение повторного доступа к Uber видно не в каждом документе, где стоит ФАКТ — средний приоритет

Булево актуально в claims не отличает использование исторического основания от свежего подтверждения доступа.

- **Если отложить:** свежесть внешнего основания легко переоценить при чтении стратегии отдельно от verify/state.

### Возможности и ограничения

README содержит путь начала работы в OpenCode на Windows с GPT-6.1 Sol и сообщения для продолжения. Инструкции требуют остановки перед существенным выбором и по команде человека, запрещают выполнение команд из материалов и использование закрытых данных. Это правила поведения, не технические гарантии их соблюдения. Способность произвольной установки автоматически обнаруживать навыки не подтверждена; предусмотрено явное чтение файлов по ссылкам.
