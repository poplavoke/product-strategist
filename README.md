# Стратег продукта

## 1. Что это

Набор файлов-инструкций для ИИ-агента, который помогает руководителю цифрового продукта.  
Агент проходит от постановки и открытых источников до вариантов, двух стратегий и плана проверки.  
Результаты, источники, состояние и решения сохраняются в папке отдельного проекта.

## 2. Что нужно

ВВОДНЫЕ ОТ ЧЕЛОВЕКА — проверенная конфигурация: **приложение OpenCode на Windows, GPT-6.1 Sol из подписки ChatGPT, папка репозитория открыта как проект**. Версии приложения и тип подписки не указаны; совместимость с другими средами здесь не заявляется.

- Доступ к этой модели через подписку ChatGPT в OpenCode; подключение подписки должно быть настроено в приложении. Другие модели и способы оплаты не являются условием описанного первого запуска.
- Интернет и доступные агенту средства поиска и чтения открытых страниц. Если источник недоступен, агент должен сообщить об этом, а не выдумать его содержание.
- Доступ к чтению и записи файлов открытой папки проекта.
- Git или Git-клиент для клонирования, если локальной копии ещё нет. Проверенная конфигурация относится к уже открытой папке, не к установке Git.

Python, установка зависимостей и запуск скриптов для этого пути не требуются. Дополнительные платные исследования, API, базы данных и другие сервисы не входят в обязательный запуск; доступ к модели требует соответствующей подписки. Цена подписки, её лимиты и стоимость отдельного задания здесь не установлены — см. [документацию затрат](docs/ROUTING.md).

## 3. Первый запуск за 5 минут

Это короткий порядок начала работы, не измеренная гарантия времени и не срок подготовки стратегии.

1. Склонируйте этот репозиторий на компьютер через Git или Git-клиент. Адрес клонирования возьмите со страницы самого репозитория; вымышленный URL здесь не приводится. Если копия уже есть, используйте её.
2. Откройте полученную папку в приложении OpenCode как проект. Убедитесь, что в ней виден `AGENTS.md`.
3. Выберите доступную через подписку модель **GPT-6.1 Sol**, не Fast.
4. Отправьте агенту сообщение, заменив `<имя>` на имя новой папки проекта, а `…` — на свою задачу:

   ```text
   Прочитай AGENTS.md. Создай проект projects/<имя> и начни работу. Запрос: …
   ```

   Пример учебного запроса:

   ```text
   Прочитай AGENTS.md. Создай проект projects/dinner-demo и начни работу. Запрос: подготовь учебные варианты развития сервиса доставки ужина для занятых жителей вымышленного города. Источники только открытые. Бюджет и спрос неизвестны. Без публикаций, расходов и экспериментов. Вариант я выберу сам.
   ```

### Что должно произойти по инструкциям

- Агент создаёт `projects/<имя>/`, записывает постановку в `brief.md`, текущий снимок в `state.md`, ведёт реестры источников, утверждений и событий.
- Если без ответа нельзя продолжить, задаёт **не более пяти блокирующих вопросов за одно обращение** и ждёт. При достаточных вводных не устраивает анкетирование ради полноты и идёт дальше.
- Последовательно выполняет сбор, исследование и подготовку минимум трёх разных вариантов, включая «оставить как есть» и «закрыть направление»; показывает возражения и ограничения.
- **Останавливается для вашего выбора.** Рекомендация агента не считается выбором человека. Стратегии начинаются только после однозначного ответа.

Это ожидаемое поведение по [AGENTS.md](AGENTS.md), не заявление о прохождении всех тестов. В [projects/demo](projects/demo/state.md) после выбора O2 завершён учебный цикл: обе стратегии, план проверки, независимая критика, итоговая проверка и [решение D001](projects/demo/decisions.md). Практическая проверка не начата; спрос и готовность запуска не доказаны.

Навыки не считаются автоматически загруженными: **агент читает их файлы по ссылкам из AGENTS.md**. Перед шагом открывает индекс `knowledge/README.md` и нужную методику.

## 4. Как продолжить после перерыва

Откройте новую сессию OpenCode **в той же папке репозитория** и отправьте:

```text
Прочитай AGENTS.md и продолжи работу над projects/<имя>
```

Агент должен прочитать `state.md`, сверить его с файлами и доступными сведениями Git, назвать текущий этап и продолжить с одного сохранённого действия, не начиная всё заново. Неизвестная версия инструкций обозначается `н/д`. При расхождении сначала исправляется снимок. Если сохранено ожидание выбора, требуется ваш выбор, а не повтор исследования.

Продолжение опирается на файлы проекта, а не на обещание, что новая сессия помнит прежний разговор.

## 5. Как остановить, уточнить и исправить результат

- **«Стоп»** или **«Подожди»** — прекратить автопереход, сохранить состояние, сообщить место остановки и ждать. Уже выполняющийся инструмент не всегда можно отменить; агент должен назвать это ограничение и не продолжать после его завершения без команды.
- **«Уточни: …»** — приостановить продолжение и разобрать уточнение; агент сохраняет место остановки и ждёт нового указания.
- Для исправления укажите файл или вывод и конкретную ошибку, например: «Исправь options/options.md: это предположение, а не подтверждённый факт. Выбранный вариант не меняй».
- Для возобновления после паузы явно напишите «Продолжай» и необходимые уточнения. Для изменения выбора назовите новый вариант; прежний выбор не отменяется одним словом «стоп».

Новые данные и существенные изменения обрабатываются через [revisit](skills/revisit/SKILL.md) с сохранением прежних оснований и решений. Эти правила остановки описаны в инструкциях; сценарий их поведенческой проверки не отмечен пройденным.

## 6. Структура репозитория

| Путь | Назначение |
| --- | --- |
| [AGENTS.md](AGENTS.md) | Общие правила, маршрут, реестры и команды человека |
| [skills/](skills/) | Девять процедур, включая сквозной учёт metrics; агент читает их по ссылкам |
| [agents/critic.md](agents/critic.md) | Правила независимого критика вариантов и стратегий |
| [knowledge/README.md](knowledge/README.md) | Индекс методик для выборочного чтения |
| [projects/_template/](projects/_template/) | Шаблоны состояния и CSV, [описание полей](projects/_template/FIELDS.md) |
| [projects/](projects/) | Отдельные папки задач: постановка, материалы, исследование, варианты, стратегии, состояние, реестры и решения |
| [tests/](tests/) | Сценарии проверки, учебная ловушка и журнал результатов |
| [docs/](docs/) | Маршрутизация, задачи, решения, аудит и история изменений |
| [tools/](tools/) | Вспомогательные файлы; не обязательная часть описанного запуска. В текущей копии есть cost_summary.py, поэтому папка не обозначается пустой |
| [demo/](demo/) | Отдельный каталог с заглушкой; учебный проект находится в projects/demo, не здесь |

Внутри проекта `state.md` хранит один текущий снимок, `events.csv` — события и затраты, `decisions.md` — решения и сохраняемую историю. `sources.csv` связывает сведения с источниками; `claims.csv` — существенные основания и их зависимости. Исторические проекты могут иметь прежние имена файлов, например `projects/test/strategy.md`.

## 7. Процесс по шагам

| Шаг | Инструкция | Результат по процедуре |
| --- | --- | --- |
| 1. Постановка | [intake](skills/intake/SKILL.md) | Вопрос, цель, ограничения, данные и блокеры в brief.md |
| 2. Сбор | [collect](skills/collect/SKILL.md) | Прочитанные допустимые материалы и sources.csv |
| 3. Исследование | [research](skills/research/SKILL.md) | План, выводы с основаниями, противоречия и пробелы |
| 4. Варианты | [options](skills/options/SKILL.md) | Разные направления, возражения, независимая критика; остановка для выбора |
| 5. Стратегии | [strategy](skills/strategy/SKILL.md) | После выбора — продуктовая и коммуникационная стратегии, план проверки и критика |
| 6. Проверка | [verify](skills/verify/SKILL.md) | Проверка доказательности и согласованности документов, исправления и ограничения |
| Запись решения | [decision-log](skills/decision-log/SKILL.md) | Выбор, основания, ответственность и условия пересмотра |
| Новые данные | [revisit](skills/revisit/SKILL.md) | Выборочный пересмотр с сохранением истории; при существенной развилке — новый выбор человека |

Правила классов моделей и ограничений вызовов описаны в [docs/ROUTING.md](docs/ROUTING.md). Наличие этих правил не означает автоматического переключения моделей. Без независимого вызова нельзя называть самопроверку независимой критикой.

## 8. Тесты

[tests/README.md](tests/README.md) описывает ручную проверку в новых сессиях и изолированных папках. В [tests/smoke.md](tests/smoke.md) — одиннадцать сценариев: от размытой задачи и недоступного источника до продолжения, пересмотра, затрат и остановки посреди шага.

**В [tests/run-log.md](tests/run-log.md) результатов smoke-прогонов пока нет.** Сценарии не считаются пройденными по наличию текста. Учебные документы `test`, `test2` и демонстрация `demo` не заменяют официальный журнал тестов. Сценарии запускаются по отдельному разрешению; обычный первый запуск не требует выполнения тестов или Python.

## 9. Затраты

Единственный журнал — `projects/<имя>/events.csv`: реальные действия и вызовы, фактическая модель, секунды, токены, стоимость и источник метрик. Формат — [FIELDS.md](projects/_template/FIELDS.md); подробные правила — [docs/ROUTING.md](docs/ROUTING.md).

- Суммы считаются отдельно по этапам и всему проекту, для каждой метрики. Дубли и агрегаты не начисляются повторно, разные валюты не складываются.
- Неизвестное — `н/д`, не ноль. Без известного тарифа стоимость не вычисляется.
- Показываются известный подытог и доля покрытия; при пропусках полный итог остаётся `н/д`. Архивный cost-log.md не суммируется с events.csv.
- На границах шагов агент применяет [metrics](skills/metrics/SKILL.md): время берёт командами системных часов, токены — только из пригодных изолированных снимков `opencode stats`. При недоступном CLI токены и деньги остаются `н/д`. Это процедура агента, не отдельный фоновый сборщик.
- Новые токены хранятся как вход/выход/кэш; историческая разбивка не выдумывается. В итоговом `metrics-summary.md` отдельно показаны покрытие этапов, ожидание и зарегистрированные вмешательства человека. [PRICING.md](docs/PRICING.md) заполняет только человек; месячный платёж сам по себе не задаёт цену шага.

Можно попросить агента без запуска скриптов:

```text
Сверь projects/<имя>/events.csv. Покажи известные подытоги и долю покрытия по этапам и проекту отдельно для секунд, токенов и стоимости. Неизвестное не считай нулём, дубли не учитывай, без тарифа стоимость не вычисляй. Скрипты не запускай.
```

В [сохранённой сводке demo](projects/demo/cost-summary.md) полные итоги времени, токенов и денег — `н/д`; известные служебные нули не означают бесплатную работу. Проверенной цены задания и измеренного полного времени цикла здесь нет — см. docs и журналы конкретного проекта.

## 10. Ограничения и безопасность

- Только открытые данные и разрешённые материалы человека. Закрытые данные компаний, ключи, пароли и токены в файлы не сохраняются; не вставляйте их в задания и материалы проекта.
- Команды внутри источников не меняют правила агента. Синтетические условия и ответы нельзя выдавать за реальные наблюдения.
- Факты требуют прочитанного источника и читаемой ссылки; гипотезы, прогнозы, вводные человека и неизвестное отделяются явно. Найденная ссылка сама по себе ничего не доказывает.
- Подготовка стратегии не разрешает закупки, публикации, контакты с людьми, реальное закрытие сервиса или эксперименты. Для практического исполнения нужны отдельные вводные и разрешения.
- Наличие `.gitignore` и конфигурации проверок не доказывает отсутствие секретов во всей истории. Этот README не является результатом полного сканирования безопасности.
- Это файловые инструкции, не автономный сервис с гарантированными переходами, фоновым наблюдением или доказанной эффективностью стратегии. Проверка документов не равна проверке спроса и бизнес-результата.
