# Контрольные списки

## Когда применять
- Перед показом вариантов, показом стратегии и закрытием решения.
- Используй только список для текущей контрольной точки.

## Принципы
- Отмечай пункт только после проверки соответствующего файла и основания.
- Неизвестное нельзя закрыть галочкой; запиши ограничение или блокер.
- Проверка не заменяет выбор человека и независимую критику.
- Статусы ставь на исследовательские утверждения, не на отчёт о проверке.

## Пошаговая процедура
1. Выбери один из трёх списков ниже.
2. Пройди пункты по файлам проекта, а не по памяти о прошлых ответах.
3. Исправь обнаруженные несоответствия в пределах текущего шага.
4. Сохрани неустранённые ограничения и покажи их человеку.
5. Обнови состояние и учёт затрат по правилам рабочего навыка.

## Перед показом вариантов
- [ ] Есть минимум три содержательно разных варианта со стабильными id.
- [ ] Включены «оставить как есть» и «закрыть направление», без фиктивной слабости.
- [ ] Различия описаны по аудитории, ценности, затратам и риску.
- [ ] Сравнение использует общие критерии; предложенные критерии явно отделены.
- [ ] Для каждого варианта есть сильное возражение и проверяемые условия успеха.
- [ ] Факты имеют читаемые ссылки; гипотезы, прогнозы и вводные человека отделены.
- [ ] Неизвестные расходы и доходы не заменены выдуманными числами.
- [ ] Критик вызван по agents/critic.md; критичные замечания обработаны по его правилам.
- [ ] После второго круга оставшиеся замечания подготовлены к показу списком.
- [ ] Подготовлен прямой вопрос о выборе; стратегия не начинается до ответа.

## Перед показом стратегии
- [ ] Выбор человека зафиксирован с условиями и источником решения.
- [ ] Названы аудитория, ситуация, задача и реальные альтернативы.
- [ ] Направление и осознанные отказы соответствуют выбранному варианту.
- [ ] Польза, плательщик, затраты и доходы связаны; единицы и периоды расчётов совпадают.
- [ ] Барьер, сообщение и роли каналов описаны; каждое обещание соответствует продукту.
- [ ] Обе стратегии согласованы друг с другом и с ограничениями человека.
- [ ] Есть ожидаемое изменение, сравнение, срок и защитные показатели.
- [ ] Правила продолжения, остановки и пересмотра заданы без подгонки результата.
- [ ] Критик вызван по agents/critic.md; критичные замечания обработаны по его правилам.
- [ ] Остаточные замечания второго круга, неизвестные и ограничения видимы человеку.

## Перед закрытием решения
- [ ] Выполнена итоговая проверка по skills/verify/SKILL.md.
- [ ] Решение, основания и осознанные отказы записаны по skills/decision-log/SKILL.md.
- [ ] Выводы не сильнее прочитанных источников; у документов есть раздел «Источники».
- [ ] Синтетические материалы помечены и не используются как доказательство спроса.
- [ ] Пробелы, противоречия и непроверенные допущения перечислены.
- [ ] Названы условия возврата к решению и следующий шаг.
- [ ] Ответственные указаны только при наличии согласования; иначе отмечен пробел.
- [ ] state.md и events.csv обновлены; реальные внешние действия не приписаны плану.

## Типичные ошибки
- Отмечать весь список без чтения файлов или считать review автоматическим одобрением.
- Скрывать незакрытый риск за общей формулировкой «всё проверено».
- Называть закрытием решения окончание наблюдения, которое ещё не проводилось.

## Мини-пример
- Учебная ситуация: стратегия написана, но у обещания нет подтверждения.
- Пункт о соответствии обещания продукту остаётся незакрытым.
- Убери обещание из внешнего текста или получи подтверждение; затем проверь пункт повторно.
