# Поля реестров проекта

Эти правила дополняют раздел «Реестры» в AGENTS.md. Примеры ниже синтетические: они показывают формат, не существующие источники, события или результаты. Файлы — UTF-8, с заголовком и неизменным порядком полей из шаблонов. Поля с запятыми, кавычками или переносами заключай в двойные кавычки; внутренние кавычки удваивай.

## claims.csv

Одна строка — одно существенное утверждение. Регистрируй посылки раньше зависимых выводов; у каждого основания вариантов, стратегий, плана и решения должны быть C-id и места использования. В читаемом документе ставь `(C012)`; для ФАКТА дополнительно нужна читаемая ссылка на источник. Сообщения о собственных действиях — события, не исследовательские утверждения.

| Поле | Смысл | Допустимые значения | Пример |
| --- | --- | --- | --- |
| id | Стабильный ID утверждения внутри проекта | C и не менее трёх цифр; уникальный, не переиспользуется и не перенумеровывается | `C012` |
| утверждение | Краткий проверяемый текст одного основания | Непустой текст без смешения факта и гипотезы; неизвестное сформулировано конкретно | `Удобство выбора времени требует проверки` |
| статус | Сила и происхождение знания | `ФАКТ`, `ГИПОТЕЗА`, `ПРОГНОЗ`, `ВЫВОД АГЕНТА`, `НЕ ЗНАЮ`, `ВВОДНЫЕ ОТ ЧЕЛОВЕКА`; не служебное состояние действия | `ГИПОТЕЗА` |
| источники | Основания из sources.csv | Существующие S-id через запятую без диапазонов; у ФАКТА хотя бы один. Пустая строка, если внешнего источника нет; фиктивный id и `н/д` вместо id запрещены | `S001,S003` |
| зависит_от | Посылки из этого claims.csv | Существующие C-id через запятую; без циклов и самоссылок. Для ВЫВОДА АГЕНТА — непустые реальные посылки; для гипотез/прогнозов — посылки, если они использованы. Пусто при отсутствии зависимостей, не выдумывать их | `C001,C004` |
| где_используется | Карта использования основания | Непустой список путей относительно проекта через запятую; после двоеточия — вариант, D-id или раздел. Файлы существуют, ссылки в них соответствуют утверждению | `options/options.md:O2,strategy/product.md:Направление` |
| актуальность | Можно ли использовать утверждение сейчас | `актуально` или `устарело`. Устаревшее сохраняется, но не служит основанием действующего решения, в том числе через цепочку | `актуально` |
| дата | Дата регистрации этой версии утверждения | Фактическая дата `YYYY-MM-DD`; при исторической неизвестности `н/д`, без придуманной даты | `2026-11-15` |
| примечание | Контекст, ограничения и прослеживаемость | Текст или `н/д`; для гипотез — основание и проверка, для прогноза — допущения и горизонт, для неизвестного — причина. Для ввода человека — дата и место/цитата. При устаревании — дата и причина, при замене — старый C-id | `Предложение агента; проверить после согласования; спрос не измерен` |

Не дублируй неизменное утверждение ради нового места использования: дополни поле. При содержательном пересмотре сохраняй прежний текст/id/дату, пометь устаревание с причиной и создай новую строку с новым C-id по revisit. Новые зависимости должны вести на актуальные основания. Историческую ссылку на старую версию храни в примечании, не в действующей цепочке посылок. Перенос старых проектов в полную схему не даёт права придумывать недостающие основания.

## events.csv

Единственный журнал событий и затрат: одна строка на отдельное действие/событие, включая неудачные попытки. Для нового исполнения шага метрики хранятся в одной строке `тип=шаг`, у вызова критика/субагента — в отдельной строке вызова его сессии. Служебные события не повторяют метрики шага. Новая сессия не создаёт повтор уже записанного события. Перед записью проверь точные и смысловые дубли, а у шага — этап, исходное время начала и session_id. Реальные повторы различай временем и номером попытки. При совпадении ключа с разными измерениями зафиксируй конфликт, не переписывай завершённую строку молча. Исторические строки сохраняются.

| Поле | Смысл | Допустимые значения | Пример |
| --- | --- | --- | --- |
| время | Когда произошло событие; для строки шага — неизменное начало исполнения | ISO 8601 с часовым поясом; если исторически известно только число — `YYYY-MM-DD`; неизвестно — `н/д`. Начало/конец активных отрезков сохраняются в источнике метрики | `2026-11-15T18:05:10+03:00` |
| этап | Где выполнялось действие | `intake`, `collect`, `research`, `options`, `strategy`, `critic`, `verify`, `decision-log`, `revisit`; для обслуживания репозитория вне продуктового цикла или неизвестного этапа — `н/д`. Старые названия этапов сохраняются как история | `research` |
| тип | Какое событие произошло | `шаг`, `действие`, `выбор модели`, `вызов модели`, `вызов сильной модели`, `ошибка`, `ошибка выбора модели`, `решение человека`, `переход`, `остановка`, `ожидание человека`, `вмешательство человека`. Исторический `итог` не включается в суммы; новые агрегаты строками затрат не добавлять | `шаг` |
| результат | Наблюдаемый исход, не план и не желаемый ответ | Непустой текст с результатом/ошибкой и номером повторной попытки, если нужен; честное `н/д`, если исход неизвестен | `Попытка 2: источник недоступен` |
| входы | Что было использовано | Пути, URL или ID, разделённые точкой с запятой; `н/д`, если не установлено; `нет` при проверенном отсутствии | `brief.md; sources.csv` |
| выходы | Что создано или изменено | Пути/ID через точку с запятой; `нет`, если выходов нет; `н/д`, если неизвестно | `research/findings.md; claims.csv` |
| причина перехода | Почему выполнено действие или изменён этап | Текст с основанием; у остановки — команда и оставшееся действие, у замены модели — исходный/целевой класс и причина; `н/д`, если неизвестно | `Команда человека «подожди»; сравнение не завершено` |
| модель | Фактическая модель, а не запрошенная | `provider/model`, с `#уровень`, только если уровень подтверждён; иначе поясни неизвестность уровня в результате. `н/д`, если модель неизвестна. У служебного события допустим ID ведущего агента с пометкой об отсутствии отдельного вызова | `openai/gpt-6.1-sol` |
| секунды | Активное время шага/вызова без ожидания человека; у закрытия ожидания — его отдельная длительность | Конечное неотрицательное число с точкой или `н/д`; источник — системные часы и команда. Неизвестные/отрицательные границы не угадывать; при неполном интервале — `н/д`. Перекрывающиеся сессии дают агент-секунды, не календарное время | `12.5` |
| токены | Непересекающиеся категории токенов шага/вызова | Новые измерения: `вход=N; выход=N; кэш=N`, каждая N — целое >= 0 либо `н/д`; все неизвестны — вся ячейка `н/д`. Нулевая/отрицательная разница stats — `н/д` с причиной по категории. Историческое целое число сохраняется как общий счётчик без разбивки | `вход=1200; выход=300; кэш=н/д` |
| стоимость | Денежные затраты этого действия | Конечное неотрицательное число с точкой в одной валюте журнала или `н/д`. По умолчанию `н/д`; расчёт только по применимому тарифу, источнику и дате из docs/PRICING.md, заполненного человеком, с определённым правилом отнесения. Плата за подписку не задаёт цену шага | `н/д` |
| источник метрики | Происхождение каждой известной метрики | Ссылка/путь/ID отчёта или описание инструмента; метод измерения или оценки, покрытие, тариф с датой и валюта для денег. `н/д`, когда всё неизвестно. Для установленного нуля объясни отсутствие затрат | `Отчёт вызова A1; секунды измерены; токены/тариф неизвестны; стоимость н/д` |

Метрики одного вызова записывай только в одну строку, обычно `вызов модели`/`вызов сильной модели`. Если они уже учтены в историческом `действие`, не дублируй их в новой строке. Диагностика ошибки или переход не расходуют эти метрики повторно. Ноль допустим при установленном отсутствии затрат, например для служебной записи без отдельного вызова; неизвестное не превращай в ноль. Реальные неудачные вызовы могут стоить денег и также учитываются один раз.

Процедура измерений — [metrics](../../skills/metrics/SKILL.md). Общие или округлённые счётчики CLI не разносить по шагам произвольно. В источнике токенов сохраняй разницы снимков с одинаковой областью и их исходные значения; счётчики текущего контекста не равны суммарному расходу. Вход/выход/кэш должны быть непересекающимися: если это не установлено, категории остаются `н/д`. Исторический скаляр не даёт покрытия новых категорий даже при значении 0.

Ожидание — две строки `тип=ожидание человека`: начало с неизвестной длительностью и конец с длительностью при известных границах; обе содержат один `ожидание_id` и его начало в `входы`. В результате явно указано `начало` или `конец`. Такие секунды исключаются из рабочего времени и показываются отдельно; открытое ожидание не означает нулевое. Для общего ожидания пересечения интервалов объединяются. Вмешательство — отдельная служебная строка с `сообщение_id` в `входы`, неизвестными метриками и моделью `н/д`; одно сообщение считается один раз. Определение вмешательства и оговорки о неполной истории — в metrics.

## Подытог и доля покрытия

Для каждой метрики отдельно: исключи точные дубли и исторические строки `тип=итог`; вычисли сумму известных значений и долю `K/N`, где K — события с известной метрикой, N — все учитываемые события. Покажи этапы и весь проект, отдельно секунды, токены и деньги. При пропусках полный итог — `н/д`; пустой журнал даёт покрытие `0/0` и неизвестный полный итог. Не складывай разные валюты, интервалы или сессионный итог с уже включёнными вызовами.

Для токенов показывай отдельные подытоги входа/выхода/кэша; общий счётчик складывается из новых категорий только при известности всех трёх и отсутствии пересечения. Неполная разбивка даёт неизвестный общий итог, но известные компоненты не теряются. Исторический общий счётчик можно включать в общий подытог, не в компонентные. События ожидания и вмешательств исключаются из знаменателя покрытия рабочих затрат и выводятся отдельно.

В `metrics-summary.md` дополнительно показывай покрытие **этапов**, не событий. Y — разные реально начатые продуктовые этапы, включая незавершённые; неизвестный этап и обслуживание репозитория — отдельно. По каждой метрике X — этапы с измерениями всех рабочих исполнений; диагностические нули не делают этап покрытым. Известная часть неполного этапа входит в известный подытог, но не повышает X. Формулировка: «известный подытог (покрытие X из Y этапов)»; при пропусках полный итог `н/д`. Отдельно указывай известный подытог ожидания с числом закрытых/открытых интервалов и зарегистрированные уникальные вмешательства с оговоркой о полноте истории. Если данных нет, не подставляй ноль.

Учебный пример: из трёх событий стоимость известна для двух и равна 0.02 + 0.03; третье — `н/д`. Известный подытог 0.05 в единой валюте, покрытие 2/3, полный итог `н/д`. Если известны только служебные нули, укажи отсутствие покрытия реальных вызовов: это не бесплатный проект. Сводка — представление events.csv, не новый журнал и не новые затраты. cost-log.md — архив, не суммировать с events.csv.
